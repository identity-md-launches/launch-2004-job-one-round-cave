Exact decimal comparison can reject legacy floating-point rounding artifacts. Optplan's proof applies only to its bounded identical-worker, integer-duration, nonpreemptive model (14 tasks and a state ceiling). Supplied estimates do not guarantee execution time. **Goal fit:** useful to any worker and distinct from the other lines. **21-piece scope:** the existing offline planning/checking goal is attainable; keep calendars, skills, actual execution and guaranteed deadlines outside it.

## Line 2 — Bounded ZIP extraction

**Tried:** all **44 SafeZip** and **16 ZipAudit** tests; both public-capture demos; digest-approved extraction of this gathering's freshly fetched public IMD API description followed by exact-tree audit. **Works:** the extracted 23,132 bytes matched the capture; ZipAudit checked both expected nodes and every byte. Its demo rejects same-size damage. Checks cover missing/extra paths, type swaps, symlinks, node limits, resource bounds, CRCs, payload hashes, cancellation and staged extraction.

**Broken:** none observed within those cases. Audit success is a momentary byte/path comparison, not a freeze or execution approval. Concurrent local filesystem mutation is outside the model; metadata, ownership and hard-link identity are not compared. Initial ZIP parsing precedes inventory limits, and cooperative seconds are not a hard CPU/RAM/deadline sandbox. **Goal fit:** general archive consumers benefit; no overlap with scheduling, arithmetic or API semantics. **21-piece scope:** portable stored/deflated ZIPs with explicit bounds in a cooperative workspace is attainable; arbitrary formats and hostile local race resistance would be too broad.

## Line 3 — Exact ZTO allocations

**Tried:** RewardSplit **15**, RewardReceipt **8**, RewardCompare **10**, RewardBatch **11** and RewardWindow **5** tests; all five demos; file-based allocation → receipt → review batches → verification, and consecutive-window scan → full recomputation. **Works:** exactly **1000000000000000000 atomic ZTO units** were conserved across the supplied address-free roster and two batches. RewardWindow's demo checks every transition from 25 through 28 atomic units and identifies the 25→26 reversal for roles `d` and `e`. RewardCompare's exit **1** is its documented arithmetic warning, not a failed command. These rosters/weights are illustrative; no recipient was invented. Metadata is the line's real historical Ethereum ZTO observation, not a new balance or price query.

**Broken:** no supported failure observed. Largest remainder is not monotonic as the total increases; the tools correctly expose that property rather than promising otherwise. Window completion exit 0 does not mean no reversals. Windows are 1–128 atomic units, not whole tokens; reports over 256 KiB fail. Caller weights establish neither entitlement nor work quality. Unsigned hashes and review batches neither prove payment nor prevent double payment. **Goal fit:** broadly useful for reproducible ZTO allocation, distinct from planning. **21-piece scope:** arithmetic allocation and bounded review evidence are achievable; do not expand into custody, execution or automatic entitlement.
